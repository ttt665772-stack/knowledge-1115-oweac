从「连不上」到「跑得慢」：一次可复用的网络排查路径

网络故障最耗人的地方，不是技术难，而是方向乱。同样是「打不开」，可能是 DNS 解析失败、路由环路、MTU 不匹配，也可能是对端服务 502。若无顺序，容易在错误层面反复试错，平均多花 40 分钟以上。下面给出一条按层次推进的排查路径，覆盖 80% 的常见场景，每步都给出可执行的判断标准和常见错误。

第一步：先定边界，10 分钟内确认「谁的锅」

步骤 1：记录故障三要素——发生时间（精确到分钟）、影响范围（单机 / 同一交换机下 3 台 / 整个办公区）、现象（完全不通 / 时通时断 / 能通但慢）。这三项决定后续 70% 的排查方向。步骤 2：做最小对照测试：同一台机器换一个目标（如访问内网网关），同一目标换一台机器（同网段另一台电脑）。两组结果组合出四种结论，直接锁定是本机、本网段还是远端问题。

步骤 3：判断「通不通」用 ping，但别只看结果。连续发 20 个包，丢包率 0%~1% 属正常，5%~20% 多为链路质量或无线干扰，超过 50% 基本是链路中断或策略拦截。延迟方面，同城内网应低于 2 ms，跨城专线通常 10~30 ms，超过 100 ms 且伴随丢包，优先查中间链路。

常见错误：一上来就重启路由器。重启能「治好」的比例不到 15%，却会清掉现场证据（日志、连接表），让后续排查时间翻倍。另一个高频错误是把「能 ping 通」等同于「服务正常」——ping 走 ICMP，业务走 TCP，两者被策略区别对待很常见。

第二步：按层推进，从物理到应用逐层排除

步骤 4（物理 / 链路层）：查网口灯、光模块收发光功率、无线信号强度。有线链路误码率应低于 1e-9，无线信号强度低于 -75 dBm 时，速率会明显下降；低于 -85 dBm 基本不可用。交换机侧看端口是否有 CRC 错包，10 分钟内增长超过 100 个，优先换线或换口。

步骤 5（网络层）：用 traceroute 定位断点。正常路径 8~15 跳，若在第 3 跳之后全是超时，说明问题在中间设备或对端策略；若前 2 跳就超时，问题在本机网关或本地网络。注意：部分设备不回应 TTL 超时，连续 3 跳超时才算有效信号。同时核对本机 IP、掩码、网关是否与所在网段一致，掩码配错（如该 /24 配成 /16）会造成「本地通、跨段不通」的典型现象。

步骤 6（传输层）：用 telnet 或端口探测确认目标端口。TCP 连接超时多为防火墙丢包，连接被拒绝（RST）多为对端服务未监听。三次握手耗时超过 3 秒，检查是否有 ACL 或安全组逐包匹配。步骤 7（应用层）：看 HTTP 状态码与 DNS 解析。DNS 解析超过 200 ms 属偏慢，超过 1 秒需检查递归服务器；解析结果与预期 IP 不一致，优先怀疑本地 hosts 或缓存污染。

常见错误：跳过链路层直接查应用，导致在「网线松了」这种 5 分钟能解决的问题上耗掉 1 小时；以及只看单次 traceroute 就下结论，未做 3 次以上对比。

第三步：抓证据，用数据替代猜测

步骤 8：抓包。在客户端与服务端同时抓，时长 30~60 秒，过滤目标 IP 与端口。判断要点：只有 SYN 没有 SYN-ACK，是去程或回程被拦；出现大量重传（重传率超过 2%），是链路质量或拥塞；出现 RST，是对端主动拒绝。步骤 9：看设备计数器。交换机端口错包、路由器接口 drops、防火墙会话数（会话表使用率超过 80% 会开始丢新建连接），这三项能在 5 分钟内定位 60% 的「时好时坏」。

步骤 10：建立时间线。把故障开始时间与变更记录对齐：配置变更、版本升级、证书到期、带宽扩容，任一项落在故障前 2 小时内，优先回滚验证。统计显示，约 50% 的突发网络故障与近期变更相关。

常见错误：抓包只抓一端，无法判断丢包发生在去程还是回程；以及不看计数器只看日志，日志级别调得低时关键丢包信息根本不会记录。

第四步：收敛与复盘，把一次性排查变成资产

步骤 11：定位后先做最小变更验证，一次只改一个变量，改完立即复测同一组指标（丢包率、延迟、端口状态）。步骤 12：记录结论：根因、影响时长、影响范围、修复动作、验证数据。若故障造成业务中断，按每小时 500~5000 元的区间估算损失（视业务类型），用于排优先级。

步骤 13：补监控。对本次暴露的盲区加告警：端口错包增长率、DNS 解析耗时、关键端口存活探测，阈值设置为正常的 2 倍，告警延迟控制在 1 分钟内。经验上，补齐 3~5 条针对性告警，可让同类故障的平均发现时间从 20 分钟降到 3 分钟以内。

常见错误：修好就结束，不记录不补监控，导致同一根因在 3 个月内重复出现 2~3 次；以及复盘只写「已恢复」，没有可复用的判断标准。

常见问题

问 1：ping 通但网页打不开，最可能是什么？
优先查 DNS 与端口。ping 走 ICMP，网页走 TCP 80/443 加域名解析。按顺序验证：解析结果是否正确、目标端口是否可连、是否有代理或证书问题。三项里通常有一项能在 10 分钟内定位。

问 2：只有部分人访问慢，从哪查起？
先按「同网段 / 跨网段」「有线 / 无线」分组对比，锁定共性。若集中在无线，查信号强度（低于 -75 dBm 需关注）与信道干扰；若集中在某一网段，查该段出口带宽与 NAT 会话数。分组对比比逐台排查快 3 倍以上。

问 3：抓包看到大量重传，说明什么？
重传率超过 2% 即可判定链路异常。可能是物理链路误码、中间设备拥塞或 MTU 不匹配（表现为大包丢失、小包正常）。先测不同包长（如 1400 与 64 字节）的丢包差异，若大包明显更差，优先排查 MTU 与分片。
